# 管理画面（Admin/Deliveries）追加開発 実装計画書

- 作成日：2026-08-21
- 対象：受付システム（reception-app）管理画面 納品書・受領書一覧／詳細
- ブランチ：`feature/admin-deliveries-enhancement`（main から分岐）

## 要件整理（5項目）

| # | 要件 | 対象画面 |
|---|------|---------|
| 1 | 「納品書追加」ボタン → 端末カメラで撮影して納品書を登録 → 完了後に詳細画面へ遷移 | Index |
| 2 | 「詳細」ボタン列を廃止し、行クリックで詳細画面へ遷移 | Index |
| 3 | ID列と書類種別列の間に画像列を追加（サムネイル表示・クリックでモーダル拡大） | Index |
| 4 | 「電子印押下」の右に削除ボタン（重複撮影された納品書の排除用） | Show |
| 5 | 「一覧に戻る」と「電子印押下」の間に「前へ」「次へ」ボタン（絞り込んだ一覧内での前後移動） | Show |

## 現状把握（調査結果）

- ルート（admin プレフィックス・`localstorage.auth`）：index / show / apply-seal / rotate-image / link-order / unlink-order のみ。**store・destroy は未実装**
- タブレット側の登録処理 `DeliveryController::store()`：画像を `delivery_documents`（publicディスク）へ保存 → 公開URLを `document_image` に格納 → token+QRコード生成 → Teams等へ通知 → Complete画面表示
- Index のテーブル列：ID／書類種別／受付日時／品名・品番／電子印状態／操作（詳細Link）
- Show のヘッダー：「← 一覧に戻る」Link＋「電子印押下」ボタン（未押印時のみ）
- `delivery_initial_order` の FK は `onDelete('cascade')` → レコード削除で紐づけも自動削除
- 一覧の絞り込み条件（delivery_type / seal_status / date_from / date_to / sort_by / sort_order）は Index 内で完結しており、Show には渡っていない

## 実装方針

### 要件1：納品書追加（カメラ撮影→登録→詳細へ）

**バックエンド**
- ルート追加：`POST /admin/deliveries` → `DeliveryController::adminStore()`（name: `admin.deliveries.store`）
- 処理は既存 `store()` を踏襲：画像保存（`delivery_documents`）→ 公開URL化 → `Delivery::create`（delivery_type・received_at=now・token）→ QRコードURL・QR画像ファイル生成
- **タブレット登録との差分**：Teams通知・delivery_received通知・即時受取通知は**送らない**（管理者の手動追加のため）。完了後は `redirect()->route('admin.deliveries.show', $delivery)`（Inertiaが詳細画面へ遷移）
- 種別は `納品書`（既定）／`その他書類` を選択可（タブレット側 store のバリデーションと同じ許容値）

**フロントエンド（Index.vue）**
- ヘッダー付近に「＋ 納品書追加」ボタン → 撮影モーダルを開く
- モーダル：`getUserMedia` でカメラ起動 → `<video>` プレビュー → 「撮影」で canvas キャプチャ → 確認プレビュー（撮り直し可）→ 種別選択 → 「登録」で `router.post`（FormData・blob）
- **複数カメラ対応（2026-08-21 追加要件）**：
  - `enumerateDevices()` で videoinput 一覧を取得しモーダル内のセレクトボックスに表示（ラベルは権限許可後に取得できるため、起動→列挙の順で処理）
  - カメラ切り替え時は現ストリームを stop してから選択 deviceId で再取得
  - 使用したカメラの deviceId を **localStorage**（キー: `admin_delivery_camera_id`）に保存し、次回モーダルを開いたとき自動選択する
  - 保存済み deviceId が無効（外付けカメラ取り外し等）の場合は既定カメラへフォールバックし保存値を更新
- モーダルを閉じる際は必ず MediaStream の全トラックを stop する（カメラ占有防止）
- ※ `getUserMedia` は HTTPS または localhost のみ動作（本番 akioka-reception.cloud は HTTPS のため問題なし）

### 要件2：行クリックで詳細遷移

- 操作（詳細）列を削除し、`<tr @click>` で `router.get(route('admin.deliveries.show', id), filters)` に遷移
- **現在の絞り込み条件をクエリとして Show に引き継ぐ**（要件5の前後移動の前提）
- 行に `cursor-pointer` と hover 強調。サムネイル等の内部クリックは `@click.stop` で遷移を抑止

### 要件3：画像列（サムネイル＋モーダル拡大）

- ID列と書類種別列の間に「画像」列を追加
- 表示画像は `sealed_document_image ?? document_image`（電子印済みを優先＝詳細画面と同じ考え方）
- サムネイル：高さ約3rem・`object-cover`・`loading="lazy"`（1ページ20件のため負荷は軽微）
- クリックで拡大モーダル（画面中央・背景クリック or ×で閉じる）。`@click.stop` で行クリックと分離
- 空データ時は「-」表示

### 要件4：詳細画面に削除ボタン

- ルート追加：`DELETE /admin/deliveries/{delivery}` → `DeliveryController::adminDestroy()`（name: `admin.deliveries.destroy`）
- 削除内容:
  1. ストレージ上のファイル削除：document_image／sealed_document_image／qr_code_file_path（公開URL→相対パス変換して publicディスクから削除。存在チェック付き）
  2. レコード削除（発注紐づけは FK cascade で自動削除。在庫加算の巻き戻しは行わない※留意点参照）
  3. `redirect()->route('admin.deliveries.index', filters)`＋フラッシュメッセージ「削除しました」
- UI：「電子印押下」の右に赤系「削除」ボタン。confirm ダイアログ（「ID:xx を削除します。元に戻せません。」）を挟む

### 要件5：前へ／次へ（絞り込んだ一覧内で移動）

- `adminIndex()` の絞り込み＋ソート構築部を private メソッド `buildAdminDeliveriesQuery(Request)` に抽出し、adminIndex / adminShow で共用
- `adminShow()` で同条件のID一覧を `pluck('id')` し、現在IDの位置から `prevId` / `nextId` を算出して Inertia props で渡す（データ量は数千件規模までこの方式で十分軽い）
- UI：「← 一覧に戻る」と「電子印押下」の間に「← 前へ」「次へ →」ボタン。端（先頭/末尾）では disabled
- 移動時も絞り込みクエリを引き継ぐ（`router.get(route(...,'id'), filters)`）
- 「一覧に戻る」も filters を引き継いで戻るよう変更（絞り込み状態の保持）

## 実装順序

1. ブランチ作成 `feature/admin-deliveries-enhancement`
2. 要件2＋3（Index：行クリック・画像列・拡大モーダル）← UI基盤
3. 要件5（filters引き継ぎ＋prev/next）← 2のクエリ引き継ぎと一体
4. 要件4（削除）
5. 要件1（納品書追加・カメラモーダル）← 最も大きい機能
6. `npm run build`・`php -l`・ローカル動作確認 → コミット

## 検証方法

- ローカル環境で管理画面を開き、以下を確認：
  - 行クリック→詳細遷移、サムネイル表示・拡大モーダル（行クリックと干渉しないこと）
  - 絞り込み（種別・電子印・日付）を掛けた状態で詳細→前へ/次へが**絞り込み結果の順序**で移動すること・端でdisabledになること・一覧に戻ると絞り込みが維持されること
  - 納品書追加：カメラ起動→撮影→登録→詳細画面へ遷移、レコード/画像/QRが生成されること・通知が飛ばないこと
  - 削除：confirm→削除→一覧へ戻る（絞り込み維持）、ストレージのファイルが消えていること
- 電子印押下・発注紐づけ等の既存機能に影響がないこと

## 留意点

- **削除は物理削除**（要件が「重複撮影の排除」のため）。誤操作対策は confirm のみ。論理削除が必要になったら別途 deleted_at 追加を検討
- 削除対象に発注紐づけ＋在庫加算（storage_address_id / added_quantity）がある場合、**在庫の巻き戻しは行わない**（重複撮影レコードには通常紐づけが無い想定。紐づけ済みレコード削除時の在庫整合は運用で対応）→ 紐づけがある場合は confirm 文言で警告を出す
- 納品書追加はPC/タブレットのカメラ品質に依存。スキャナ経由の正式フロー（タブレット受付）の代替ではなく補完機能の位置づけ
- 本番反映は別途承認後（このブランチは main 未マージのまま報告）
